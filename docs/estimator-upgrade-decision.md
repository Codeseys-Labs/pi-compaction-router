# The optional estimator upgrade (ai-tokenizer): NOT TAKEN in W3

Verdict §2 steal 8 offers a real Claude tokenizer as an *optional* upgrade past steal 1's
`serializeConversation`-based estimator, and the W3 brief makes the obligation conditional: "**if**
ai-tokenizer is vendored as the optional estimator upgrade it MUST carry a tokenize-cost cap +
honest `tokens_skipped` flag, A-vs-B drift benchmark as acceptance shape".

It is not vendored. This file is the decision, written down rather than left as an absence, because
"the row is silent about it" and "the row decided against it" are different facts — the same reason
the ledger has an `unobserved` outcome.

## Why not

1. **The artifact at the named commit is Rust, and it is 1.6 MB.** AFT `566bcde` carries the
   tokenizer as `crates/aft-tokenizer/` — `claude.rs` (158 lines of BPE over `fancy_regex`) plus
   `claude_data.rs`, **65 002 lines / 1 515 241 bytes** of generated encoder tables. There is no
   TypeScript in it. Vendoring it into a pi extension would mean either shipping a Rust build and a
   bridge process (which is the AFT architecture the dive explicitly declined — "adopting a Rust
   binary, a bridge process, an ONNX runtime, a 22 MB repo and a 14 k-line plugin in order to gain
   zero lines of compaction logic") or re-generating the tables in TS, which is new work, not a
   steal.

2. **The TS route is an npm tarball, which the steal discipline forbids.** `claude.rs`'s own header
   says it is "Generated by build.rs from ai-tokenizer Claude encoding". So the TypeScript form of
   this mechanism is the `ai-tokenizer` npm package — and verdict §2's header rule is "All foreign
   code is taken from **named commits** (never npm tarballs)". `ai-tokenizer` has no named commit in
   the steal table. Taking it would be exactly the hazard the rule exists for, and this wave has a
   worked example of why: POM's npm 3.0.3 is 26 days behind its `main` under the same version
   string, and Accordion's npm predates the code W3 *did* steal from it (`recordPlanOutcome` is
   absent from `@a-fig/accordion@0.1.2` entirely).

3. **The upgrade is optional, and its premise is already served.** Steal 8 is framed as an upgrade
   *past* steal 1. W1 landed steal 1: the estimator now measures the artifact `compact()` actually
   sends, via pi's own exported `serializeConversation`/`convertToLlm`, which closed the measured
   3.7×–37.9× over-count that falsely refused 5 of 14 real sessions. The remaining error is a
   deliberate over-estimate on a **fit guard**, not a billing path. A precise tokenizer would narrow
   it; nothing currently observed requires that.

## What was taken from steal 8 anyway

Declining the tokenizer did not mean declining the discipline around it. Both of these are in
`src/ledger.ts`, with per-file provenance headers:

- **The tokenize-cost cap and the honest flag** (stealList 3, `registry.rs:64` and `:4438-4452`):
  `TOKENIZE_CAP_BYTES = 128 * 1024` — upstream's value — with `tokensAfter: null` plus
  `tokensSkipped: true` past it, and a savings aggregate that excludes skipped events and reports
  the exclusion. Upstream's rule, *never fabricate a count when you declined to compute one*, is
  worth holding for a chars/4 estimate too: the failure it prevents is a pathological summary
  silently reporting a 100 % saving.
- **The savings telemetry and its status surface** (stealList 4): `savingsPercent` is upstream's
  `compressionSavingsPercent` including both edge cases upstream's own tests pin, and the two-scope
  session/project shape is upstream's `StatusCompression`.

## What a future vendoring owes (the acceptance shape)

If the tokenizer is ever taken, stealList 2's A-vs-B methodology is the gate, and it is a gate about
*routing decisions*, not about token counts:

1. Named commit for whatever artifact is used, recorded in `NOTICE` with a per-file header.
2. Report **overall and per-item** drift plus **p95 absolute** drift of the new estimate against the
   current one, over a corpus of real transcripts — not a single aggregate ratio.
3. The decision metric: **how often the conservative estimate skips a target that would have fit.**
   That is what the estimator exists to get right, and a tokenizer that improves mean accuracy while
   changing no routing decision has bought nothing.
4. The cap and the flag come with it, sized for the new cost. A real BPE pass is orders of magnitude
   more expensive than `length / 4`, so the cap stops being a formality — AFT measured 6.22 ms for 26
   fixtures, and a 268 k-token history is not 26 fixtures.
